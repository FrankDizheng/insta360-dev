# 燕窝玻璃瓶压入式装盒方案（Phase 2 Milestone）

## 1. 目标与边界

当前 demo 已完成视觉识别、抓取、抬升、搬运和基础放置。  
本阶段的目标不是重做抓取，而是在现有平台和现有机械臂 demo 基础上，补齐 `Platform Internal` 中已经规划但尚未落地的“力/力矩传感”能力，使系统能够完成压入式装盒。

本阶段需要实现：

- 识别包装盒整体位姿和目标空槽
- 抓取燕窝玻璃瓶并搬运到目标槽位上方
- 在压入末端检测接触、判断偏斜或卡滞
- 按目标力完成压入，到位后松爪并安全退出

技术边界：

- 首版只针对单一瓶型、单一盒型
- 首版目标是跑通稳定闭环，不追求量产极限节拍
- 本阶段沿用现有平台架构，只做增量扩展

## 2. 硬件配置

### 2.1 复用现有硬件

以下硬件沿用现有 demo，不属于本阶段新增采购：

| 硬件 | 用途 |
| --- | --- |
| 现有机械臂 | 执行抓取、搬运、下探、压入、回退 |
| 现有电动夹爪 | 抓瓶、保持、释放 |
| 现有控制计算单元 | 视觉、任务编排、参数管理、日志记录 |
| 现有边缘执行单元 | 机器人接口、实时状态回传 |

### 2.2 本阶段新增硬件

与 `Platform Internal` 保持一致，本阶段核心新增硬件如下：

| 硬件 | 是否必需 | 用途 | 集成方式 |
| --- | --- | --- | --- |
| 六维力/力矩传感器 | 必需 | 接触检测、过压保护、偏斜识别、恒力压入 | 安装在 `机器人法兰 -> 力传感器 -> 夹爪` 之间 |
| 装盒区顶视工业相机 | 必需 | 识别盒位、空槽、已装瓶状态 | 固定安装在装盒工位上方 |
| 取料区固定视觉（若现有链路不稳定） | 条件必需 | 识别待抓瓶位置 | 仅在现有取料视觉稳定性不足时补充 |

建议但不是首版必须：

- 夹爪软质防滑摩擦片
- 腕部或近距修正相机
- 传感器转接板 / 快换板
- 简单导向治具

## 3. 任务步骤与新增 Action

当前任务可拆成 8 个主步骤：

1. 识别包装盒整体位姿和目标空槽
2. 识别待抓取瓶子
3. 抓取并抬升
4. 移动到目标槽位上方安全位
5. 二次修正放置位姿
6. 低速下探并检测接触
7. 恒力压入并判断是否到位
8. 松爪、回退、记录结果

在现有 `move_above / grasp / release` 基础上，本阶段建议新增以下标准 action：

| Action | 用途 |
| --- | --- |
| `detect_box_pose` | 识别盒位和装盒坐标系 |
| `detect_empty_slot` | 识别空槽位置 |
| `refine_place_pose` | 压入前做局部位姿修正 |
| `read_force` | 读取六维力/力矩数据 |
| `move_until_contact` | 低速下探直到检测到接触 |
| `force_press` | 按目标力执行压入 |
| `verify_inserted` | 判断是否压入到位 |
| `release_and_retreat` | 松爪并安全退出 |

说明：

- `contact_detect` 不建议单独做成远端 action，而应作为边缘侧实时判断逻辑的一部分
- 这组 action 后续可直接复用到插接、压装、卡扣装配等接触式任务

## 4. 新增软件与集成方式

本阶段不推翻现有架构，只做增量扩展。

### 4.1 边缘侧新增软件

部署在 Pi / 机器人侧：

- `force_sensor_driver`
  - 读取六维力/力矩传感器数据
  - 输出统一格式的 `Fx/Fy/Fz/Mx/My/Mz`
- `contact_monitor`
  - 在边缘侧实时判定接触、过压、侧向力异常和卡滞征兆
  - 该模块必须靠近传感器侧，不能放在主控侧，否则无法满足响应时延目标
- `force_press_controller`
  - 执行恒力压入或位置/力混合控制

### 4.2 主控侧新增软件

部署在 Mac / 上位机：

- `box_slot_detection`
  - 识别盒位、空槽、已装瓶状态
- `placement_state_machine`
  - 将现有 pick-place 扩展为：
    - detect
    - pick
    - pre-align
    - contact search
    - force insert
    - verify
    - release
    - retreat
- `near_view_refinement`
  - 可选，用于压入前二次修正

### 4.3 平台侧新增软件

- `recipe_manager`
  - 维护瓶型 / 盒型 / 内衬的参数配方
- `force_trace_logger`
  - 记录力曲线、位移、动作结果
- `failure_analyzer`
  - 归类过压、偏斜、卡滞、未到位等失败原因

### 4.4 如何接回现有机械臂系统

现有系统从：

- `detect -> grasp -> move -> place`

扩展为：

- `detect -> grasp -> move -> refine -> contact -> force_press -> verify -> release`

具体集成方式：

- 保留现有机械臂控制与抓取链路
- 在边缘侧新增力传感器驱动、接触监测和力控执行模块
- 在主控侧新增装盒识别与压入状态机
- 在平台侧新增配方管理和力曲线记录

## 5. 与 Platform Internal 的一致性

本方案与 `Platform Internal` 一致，不是另起一套系统。

在 `Platform Internal` 中已经规划了：

- 硬件抽象层包含 `力/力矩传感`
- 标准动作协议和动作层可扩展 `read_force`
- 数据层记录动作日志、力传感数据和执行结果

因此本阶段本质上是把平台里已经规划过的三类能力落地：

1. 硬件抽象：把六维力传感器接入现有机器人系统
2. 动作抽象：把 `read_force / move_until_contact / force_press` 纳入标准 action
3. 数据抽象：把压入过程中的力曲线、位移和失败原因沉淀为可复用数据

这也是本阶段的核心价值：不是只完成一个装盒场景，而是把平台推进到“支持接触式工业操作”的下一阶段。

## 6. 目标指标

本阶段按工程可落地目标设定，并与 `Platform Internal` 中已有的力控指标保持一致。

### 6.1 响应与灵敏度

| 指标 | 建议目标 |
| --- | --- |
| 六维力采样频率 | 目标 `1 kHz`，可接受范围 `500-1000 Hz` |
| 接触检测响应时延 | `<= 10 ms` |
| 过压保护触发时延 | `<= 5 ms` |
| `Fx/Fy/Fz` 分辨率 | `<= 0.1 N` |
| 力矩分辨率 | `<= 0.005-0.01 N·m` |
| 压入力稳态误差 | `<= ±0.5 N` |

### 6.2 首版控制建议

| 参数 | 建议值 |
| --- | --- |
| 接触搜索速度 | `10-30 mm/s` |
| 压入速度 | `5-15 mm/s` |
| 接触阈值 `Fz_contact` | `1.0-2.0 N` |
| 目标压入力 `Fz_target` | `8-15 N` |
| 压入力上限 `Fz_max` | `18-25 N` |
| 侧向力上限 `Fx/Fy_max` | `3-5 N` |
| 回退距离 | `5-15 mm` |
| 最大重试次数 | `2-3 次` |

### 6.3 首版效率目标

| 指标 | 目标 |
| --- | --- |
| 单次节拍 | `6-8 秒 / 瓶` |
| 成功装盒率 | `>= 95%` |
| 压入到位率 | `>= 95%` |
| 破损率 | `0` |

## 7. 结论

本阶段的核心不是增加很多分散功能，而是补齐一个关键能力：

- 让现有机械臂从“能抓能放”
- 升级为“能接触、能检测、能压入、能回退”

为完成这个任务，核心新增内容只有三类：

1. 新增六维力/力矩传感器
2. 新增与力控压入相关的软件能力和标准 action
3. 将这些能力接回现有平台和现有机械臂流程

如果第一阶段验证的是视觉抓取，那么第二阶段验证的就是平台是否真正具备接触式工业操作能力。
